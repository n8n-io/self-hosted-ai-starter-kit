# CLI internals

Where things live in `packages/cli`, how the command line is parsed, how `.env` files are handled and what the schemas guarantee. Paths are relative to `packages/cli/`.

## Build setup

- `tsdown.config.ts`: entry `src/index.ts`, `platform: 'node'`, `dts: false`, `clean: true`, producing one bundle `dist/index.mjs` (`#!/usr/bin/env node`, bin `n8n-starter`).
- Package scripts (from `packages/cli/`, or `pnpm --filter n8n-starter-cli run <script>` from the root): `build`, `dev` (`tsdown --watch`), `start` (`node dist/index.mjs`), `test` (`vitest run`), `typecheck` (`tsc --noEmit`, covers `src` and `tests`), `release` (bumpp).
- `tsconfig.json` is strict with `verbatimModuleSyntax` (use `import type`), `noUnusedLocals`, `module: preserve`, `moduleResolution: bundler`.

## Command line, options and help

- The command line is `<command> [sub-command] [value] [options]`. `config` takes a key and a value, `models`, `secrets` and `tilt` a sub-command and a value; the other commands reject extra arguments with exit 1.
- `--log-level silent|error|warn|info|debug` (default `info`) and `-q` / `--quiet` (= `error`). An explicit `--log-level` wins over `--quiet`; a bare `--log-level` or an unknown value exits 1 and lists the levels.
- `--json` is accepted by `verify`, `models read` and `secrets read` (passed as `{ json }`); every other command rejects it with exit 1.
- `-h` / `--help` and `help [command]` print the global help, or the help of the command named on the command line (`secrets -h`, `secrets read --help`, `-h secrets`, `help secrets`), with exit 0; an unknown name is an unknown command (exit 1). Both come from `renderHelp()` in `src/help.ts`, so the global help and the per-command help never drift. The usage column is cyan through `styleText` (plain without a tty or with `NO_COLOR`, the padding counts the plain length); the headings are not styled so tests can match `Usage:` lines verbatim.
- A usage error (unknown command, extra arguments to a command without sub-commands, a missing or unknown sub-command for `models`, `secrets` or `tilt`) prints the reason on stderr and the help of the command on stdout with exit 1 before the module runs; the modules keep their own missing/unknown checks for direct calls.

## State and `.env` handling

- The state the CLI manages: one `.env` next to every `.env.template`, the secret values inside them that a `.env.json` declares, a `.env.secrets` beside the `.env` for the declared secrets no container reads (see the Secrets section of SPEC.md) and the two external docker networks. `secretPath`, `secretValue` and `isSecretUnfilled` of `src/commands/secrets.ts` pick the file of an entry: never read `directory.env[key]` for a declared secret.
- `findFiles` skips `node_modules`, `dist` and every dot-directory, which keeps `.volumes/` and `.git/` out of `setup`, `verify` and `reset` (a test covers it).
- `updateEnvContent(content, updates)` replaces `KEY=value` lines in place (regex `^([A-Z_][A-Z0-9_]*)=`, case-insensitive), keeps comments, blank lines and unrelated keys, and appends keys that were not present. Every value goes through `formatEnvValue`: plain when no reader takes part of it as syntax, in single quotes otherwise (compose interpolates `$` in an unquoted value, node cuts one at `#`), and an error without the value for a single quote, a backslash or a line break.
- The root `.env.template` defaults are tested against the first entry of each schema list (`tests/config.test.ts`): changing a default means changing the template, the schema order and the Configuration block of SPEC.md together.
- `config` writes only the one key it was asked for (for `N8N_ASSISTANT` also the model keys of `compose/n8n/.env`, before the toggle); `configSchema` is strict about shapes (`DOMAIN` hostname regex, `AI_MODELS` comma-separated lowercase ids or empty) and `configSchema.shape[key]` validates a value given on the command line.
- `CONFIG_KEYS` (template order) and `CONFIG_KEY_DESCRIPTIONS` mirror the root `.env.template`: every key of the template and the comment line above it (`tests/config.test.ts` checks both). The descriptions open the hints of the key select, followed by the available values (`keyHint`, current ones in green via `styleText`).

## Schemas

- `AI_RUNTIMES`, `AI_ENGINES`, `N8N_VARIANTS`, `N8N_ASSISTANTS` in `src/schemas/config.ts` are the typed source of every option list, and the first entry is the default everywhere. `N8N_ASSISTANT` defaults to `false` in `configSchema`, so a root `.env` written before the key existed stays valid. The `N8N_VARIANT_CASCADE` keys in `src/commands/tilt.ts` are typed by them, so the compiler enforces that mirror; the others are listed in the mirrors table. `AI_GATEWAYS` is the exception: no gateway runs by default, so `aiGatewaySchema` puts the empty value first, `configSchema` defaults a missing key to it and the template leaves `AI_GATEWAY=` empty.
- `src/schemas/models.ts` is the shape of `compose/models/models.json`, mirrored by `compose/models/models.schema.json` for editors (the fields: models reference of the compose-catalogue skill). What the schema adds: `.strict()` on the model and on each engine block, unique ids, at least one block, `memory` a positive number, `note` and `runtimes` non-empty when present. Tests check that the repository catalogue serves every model on both engines and that the editor schema carries the same pattern, length, blocks and types.
- `src/schemas/assistant.ts` is the shape of `compose/models/models.assistant.json`, mirrored by `compose/models/models.assistant.schema.json`: `.strict()` providers with at least one model each, unique ids per level, and the two id patterns the editor schema repeats (`tests/assistant.test.ts` compares them and checks that the first model is the compose default).
- `src/schemas/secrets.ts` is the shape of a `.env.json` (`.strict()`, a discriminated union on `source`, inside `generate` a second one on the `type` of its `generator`, defaults for `rotation`, `file` and the generator fields, the generator itself through `.prefault({ type: 'random' })` so its field defaults apply, `required` typed by the config enums and allowed on a `prompt` and on a `link`, which it makes conditional), mirrored by `compose/.env.schema.json`; cross-entry rules (a link resolves to a non-link entry, a generator `input` to a random `generate` entry of the same manifest) live in `readSecretManifests`, template and compose rules in the repository test of `tests/secrets.test.ts`.
- `src/schemas/tilt.ts` is the shape of the `tilt resources` output, `.strict()` throughout, with refinements over the whole plan (unique names, known dependencies, enabled resources only depend on enabled ones). `tiltResources()` parses its own result through it before printing.
