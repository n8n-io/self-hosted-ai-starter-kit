# n8n-starter CLI rules

Operational rules for `packages/cli`, the `n8n-starter` CLI that the root scripts (`pnpm run setup|verify|config|reset`) and the [Tiltfile](../../../../Tiltfile) call as `node packages/cli/dist/index.mjs <command>`. The section "n8n-starter CLI" of [SPEC.md](../../../../SPEC.md) holds the behaviour contract; [packages/cli/README.md](../../../../packages/cli/README.md) is the package's own usage page.

## Stack and build

- TypeScript ESM: `@bomb.sh/args` (flags), `@clack/prompts` (output and prompts), `zod` (root `.env` and catalogue schemas). `portless` is in `dependencies` but unused (see Scaffolding).
- `tsdown.config.ts`: entry `src/index.ts`, `platform: 'node'`, `dts: false`, `clean: true`, producing one bundle `dist/index.mjs` (`#!/usr/bin/env node`, bin `n8n-starter`).
- `dist/` is gitignored and consumed by the root scripts and the Tiltfile (its `verify()` fails the Tiltfile load when the bundle is missing). **Every source change needs `pnpm -r run build` (= `pnpm run build`) before `pnpm run <command>` or Tilt see it.** Tests run against `src/`, so green tests do not mean a rebuilt CLI.
- Package scripts (from `packages/cli/`, or `pnpm --filter n8n-starter-cli run <script>` from the root): `build`, `dev` (`tsdown --watch`), `start` (`node dist/index.mjs`), `test` (`vitest run`), `typecheck` (`tsc --noEmit`, covers `src` and `tests`), `release` (bumpp). `tsconfig.json` is strict with `verbatimModuleSyntax` (use `import type`), `noUnusedLocals`, `module: preserve`, `moduleResolution: bundler`.
- CI (`.github/workflows/ci.yml`) runs lint, build and test on Node 24. Typecheck is not in CI; run it locally.

## Command lifecycle

Every command takes `rootDir = process.cwd()` (the root scripts run from the repo root) and, where docker is involved, `docker: DockerOptions` with an injectable `run`.

| Command | Steps | Exit code |
| --- | --- | --- |
| `setup` | `findFiles(rootDir, '.env.template')`, copy each to `.env` beside it with `COPYFILE_EXCL` (`EEXIST` means `skipped`, never overwrites), then, when a root template exists, `applyDetectedRuntime` (`detectPlatform`, an info line `Detected …`; a root `.env` created in this run gets the detected `AI_RUNTIME` when the template value differs, a skipped one only a `runtimeMismatch` warning), then `fillSecrets` (every unfilled `generate` key of every manifest gets a random value, then every `link` is set to its source; logs `Generated`/`Linked` lines) and a warning per `prompt` key the root `.env` requires but is unset (`checkSecrets` with `readRootConfigIfValid`), then `ensureDockerNetworks(['n8n-starter-public', 'n8n-starter-private'])` (creates only the missing ones, `--driver bridge`), then a summary line | 1 when docker is unreachable (the `.env` files are still created) or a manifest is invalid |
| `verify` | `checkRequirements` (node, the docker daemon and docker compose against `REQUIREMENTS`; too old or not queryable fails), `verifyEnvFiles` (a `.env` next to every template), `checkSecrets` over `readSecretState` and the root config (`missing`, `mismatch` and `required` fail, `unset` is info, `ok` success; an invalid manifest is `secretsError`) and `verifyDockerNetworks`, then, unless docker failed, `detectPlatform` and `runtimeMismatch` against the root config (`platform`, `runtimeWarning` of the result; `ok` ignores both); `formatVerifyResult` buckets the lines (`Detected …` as info, the mismatch as a warning without a hint) (`success`, `info`, `warnings`, `errors`: `Found` / `Missing` per item, one line per secret through `formatSecretCheck`) and adds the `pnpm run setup` hint only when a file, a generated or linked secret or a network is missing and the README Prerequisites hint only when a tool version fails; text mode logs the buckets (`hints` through `logger.hint`, gated at the error level under `💡`), `{ json: true }` prints the report once with `console.log` and nothing else | 1 when a tool is too old or missing, any file, secret or network is missing or stale, a manifest is invalid or docker cannot be queried |
| `config [KEY] [value]` | read the root `.env` (missing: error "Run `n8n-starter setup` first", exit 1); resolve the key (no `KEY`: `select` over `CONFIG_KEYS`, hint from `keyHint`: description plus the available values with the current one in green; unknown `KEY`: error listing the keys, exit 1); `AI_MODELS` (chosen or named) returns `models(rootDir, ['select', value?], { intro: false }, docker)`, so everything from here on is the `models select` row below; for the other keys resolve the value (`value` given: `configSchema.shape[key]`, else error and exit 1 without a prompt; otherwise one prompt: `DOMAIN` text, `N8N_VARIANT`/`AI_RUNTIME`/`AI_ENGINE`/`AI_GATEWAY` select (the empty option of `AI_GATEWAY` reads `none`; a set gateway logs its endpoint with `logGatewayEndpoint`); `AI_RUNTIME` first runs `detectPlatform` (info line `Detected …`), marks the suggested option with a green `(detected)` in its label (a clack `hint` shows on the focused row only) and warns with `runtimeMismatch` after the write); `updateEnvContent` with that one key; write; `AI_ENGINE`/`AI_RUNTIME` then read the catalogue (a failure is a warning), `AI_ENGINE` prints where n8n reaches each model and both warn about `AI_MODELS` ids the new combination does not serve (kept as they are, pointer to `models select`) | 1 on an unknown key or a rejected value (for `AI_MODELS` also a missing catalogue); a cancel leaves the file untouched |
| `models read [filter] [--json]` | `readModelsCatalogue`, `listModels(catalogue, filter)` (engines in `AI_ENGINES` order, models in catalogue order, kept when the engine or id contains the filter, case-insensitive); text: per record a header `<engine>/<id>` and `keyValue` lines for `model`, `label`, `args`, `memory`, `note`, `runtimes` (joined with `,`) when present, blank line between records; `{ json: true }`: the records as one array; `console.log` once, nothing else on stdout | 1 naming the file when the catalogue is missing or invalid, or the filter when nothing matches; 1 listing `read, select` on a missing or unknown sub-command |
| `models select [ids]` | read the root `.env` (missing: same error as `config`, exit 1) and the catalogue (error, exit 1); `ids` given: `validateModels` (`aiModelsSchema`, then every id served by the current engine on the current runtime), else error and exit 1 without a prompt; otherwise `promptModels`: `detectPlatform` (info line `Detected …`), multiselect over the engine's entries (`modelOptions` with the docker memory: an estimate above it is pointed out in yellow on a cpu runtime, never disabled), runtime-incompatible ones disabled, current ids preselected, skipped (`''`) when nothing runs on the runtime; `updateEnvContent` with `AI_MODELS` only; write; `logModelEndpoints` | 1 on a rejected value or a missing `.env` or catalogue; a cancel leaves the file untouched |
| `tilt resources` | `readRootConfig` (the root `.env` through `configSchema`), `readModelsCatalogue`, `secretDirectories` (which projects get a secrets button in the Tiltfile), `tiltResources(config, catalogue, secretDirs)` (fails on an `AI_MODELS` id not served by the engine on the runtime, listing the served ids; the result is parsed through `tiltResourcesSchema`), `console.log(JSON.stringify(plan, null, 2))`; no intro, no outro, nothing else on stdout | 1 with the reason on a missing or invalid `.env`, catalogue or model id; 1 listing `resources` on a missing or unknown sub-command |
| `secrets read [filter] [--json]` | `readSecretState`; an exact key (case-insensitive) prints only its values, otherwise `listSecrets(state, filter)` (substring of the directory or key) printed as the relative `.env` path followed by `KEY=value` lines, groups separated by a blank line; with `{ json: true }` one array of `{ file, key, value, source }` in the same order (`value` null while the key is absent, an exact key narrows the array); `console.log` once, nothing else on stdout | 1 naming the file when a matched `.env` is missing, when nothing matches, or on an invalid manifest; 1 listing `read, set` on a missing or unknown sub-command |
| `secrets set KEY [value]` | `readSecretState`; `KEY` must be a `generate` or `prompt` key (a link is refused naming its source key, an unknown key lists the keys); `value` given: written as is (empty rejected); otherwise one `password` prompt with the entry's `description`, cancel writes nothing; a filled `rotation: never` key warns first; `setSecret` writes the key and every link of it, logging `set`/`linked` per file, never the value | 1 on a missing key, an unknown or link key, an empty value, a missing `.env` or an invalid manifest |
| `reset` | `findFiles(rootDir, '.env')`, list them, warn about the filled `generate` keys with `rotation` `manual` or `never` (a manifest problem is ignored here), `confirm` (default `false`), `rm` each | 0; a cancel deletes nothing |

Contracts to keep:

- `verify` is the Tiltfile's gate and runs there as `verify --json || true` inside `local(..., quiet=True)`: stdout holds exactly one JSON report `{ ok, success, info, warnings, errors, hints }`, the Tiltfile forwards `warnings` to `warn()` and `fail()`s with `errors` (marked `❌`) and `hints` (marked `💡`) when `ok` is false (`local()` cannot read an exit code, hence `|| true`); the report itself carries no markers, the consumer renders them. In text mode `--log-level error` prints nothing on success and only the failed checks and hints otherwise. Never add output that bypasses `logger` (or the one `console.log` of the json mode).
- `tilt resources` is the Tiltfile's plan and runs there with `--log-level error` inside `local(..., quiet=True)` and `decode_json`: on exit 0 stdout holds exactly one JSON document, on exit 1 Tilt shows the logged reason. `models read`, `secrets read` and `verify --json` follow the same stdout contract (the `key=value` lines carry colour codes only on a tty). These four are the only commands, with `--help` and `--version`, that use `console.log`.
- The Tilt topology lives in `tiltResources()` (`src/commands/tilt.ts`): compose files relative to the Tiltfile, project names, profiles, inline overrides, resource deps, links, labels, `auto_init` and `enabled` per variant and engine. Change it there with a test in `tests/tilt.test.ts`; the Tiltfile is a loop over the plan and should not grow conditions.
- `setup`, `secrets set` and `reset` are the only writers of per-service `.env` files; `config` and `models select` edit the root one only. Nothing ever overwrites a filled value (a link follows its source, that is the one derived value) or touches an existing docker network; `setup` fills a secret that is absent, empty or still equal to its template value, and sets `AI_RUNTIME` only in a root `.env` it created in the same run (a `skipped` one gets a warning at most).
- Commands are idempotent: re-running them changes nothing that is already in place.
- User-facing text names the CLI `n8n-starter` in intros and help; every "run …" hint names the root script through `runCommand()` of `src/utils/format.ts` (`pnpm run setup`, `pnpm run secrets set KEY`), since the root scripts are the only documented way to run the CLI (no global install).

## Global options and the logger

- `--log-level silent|error|warn|info|debug` (default `info`) and `-q` / `--quiet` (= `error`). An explicit `--log-level` wins over `--quiet`; a bare `--log-level` or an unknown value exits 1 and lists the levels. `--json` is accepted by `verify`, `models read` and `secrets read` (passed as `{ json }`), every other command rejects it with exit 1.
- `-h` / `--help` and `help [command]` print the global help, or the help of the command named on the command line (`secrets -h`, `secrets read --help`, `-h secrets`, `help secrets`), with exit 0; an unknown name is an unknown command (exit 1). Both come from `renderHelp()` in `src/help.ts`, so the global help and the per-command help never drift; the usage column is cyan through `styleText` (plain without a tty or with `NO_COLOR`, the padding counts the plain length), the headings are not styled so tests can match `Usage:` lines verbatim. A command that needs a sub-command (`models`, `secrets`, `tilt`) called without one, or with an unknown one, prints the reason on stderr and its help on stdout with exit 1 before the module runs; the modules keep their own missing/unknown checks for direct calls.
- `logger` (`src/utils/logger.ts`) wraps clack's `intro`, `outro`, `log.success|info|step|warn|error|message` and `cancel`, gated by one process-wide level (`intro`, `outro`, `success`, `info`, `step` at info; `warn`, `cancel` at warn; `error` and `hint` at error, `hint` with the `💡` symbol (`HINT_SYMBOL`) so a fix never looks like a failure; `debug` at debug with the `○` symbol). The per-level symbols are clack's own, with their ASCII fallbacks; never prepend a second marker to a message. Use it for every line of output; `console.log` is reserved for `--help` and `--version`.
- Interactive prompts are input, not output: the log level never silences them.
- `@bomb.sh/args` types a flag by its raw key before resolving aliases, so every short alias (`h`, `v`, `q`) and every value-less flag (`json`) is listed in `boolean`; otherwise it swallows the next token as its value.
- The command line is `<command> [sub-command] [value] [options]`. Positional arguments come from `positionals(argv)` in `src/index.ts`, not from the parser's `_`: the parser coerces them (`123` to a number, `true` to a boolean, `""` dropped, everything after `--` dropped). `config` takes a key and a value, `models`, `secrets` and `tilt` a sub-command and a value; the other commands reject extra arguments with exit 1. pnpm forwards `pnpm run config KEY value --log-level error` unchanged; never document a `--` separator (pnpm passes it through and the parser then drops what follows).

## State and `.env` handling

- The state the CLI manages: one `.env` next to every `.env.template` (today the root, `compose/proxy/traefik`, `compose/n8n`, `compose/storage/postgres`, `compose/storage/pgadmin`, `compose/services/qdrant`, `compose/models/ollama`, `compose/models/vllm`, `compose/models/litellm`), the secret values inside them that a `.env.secrets.json` declares (`compose/n8n`, `compose/storage/postgres`, `compose/storage/pgadmin`, `compose/models/litellm`, `compose/models/vllm`; see the Secrets section of SPEC.md) and the two external docker networks.
- `findFiles` skips `node_modules`, `dist` and every dot-directory, which keeps `.volumes/` and `.git/` out of `setup`, `verify` and `reset` (a test covers it).
- `updateEnvContent(content, updates)` replaces `KEY=value` lines in place (regex `^([A-Z_][A-Z0-9_]*)=`, case-insensitive), keeps comments, blank lines and unrelated keys, and appends keys that were not present. `parseEnvContent` is node's `util.parseEnv`.
- The root `.env.template` defaults are tested against the first entry of each schema list (`tests/config.test.ts`): changing a default means changing the template, the schema order and the Tiltfile comments together.
- `config` writes only the one key it was asked for; `configSchema` is strict about shapes (`DOMAIN` hostname regex, `AI_MODELS` comma-separated lowercase ids or empty) and `configSchema.shape[key]` validates a value given on the command line.
- `CONFIG_KEYS` (template order) and `CONFIG_KEY_DESCRIPTIONS` mirror the root `.env.template`: every key of the template and the comment line above it (`tests/config.test.ts` checks both). The descriptions open the hints of the key select, followed by the available values (`keyHint`, current ones in green via `styleText`).

## Interactive prompts

- Primitives: `text`, `select`, `multiselect`, `confirm`, `password` (secrets, masked) from `@clack/prompts`. Every result is checked with `isCancel`; a cancel logs `logger.cancel(...)` and returns without writing.
- `config` runs at most two prompts: the key select (only without `KEY`) and the prompt of that key (`promptDomain`, `promptChoice` in `src/commands/config.ts`, each returning `undefined` on cancel; for `AI_MODELS` the second one is the prompt of `models select`). `models select` runs one prompt, `promptModels` in `src/commands/models.ts`. With a value on the command line no prompt runs at all.
- `text` validation delegates to a zod schema (`domainSchema.safeParse(value).error?.issues[0]?.message`), so error messages live in the schema.
- `select` options come straight from the schema tuples (`N8N_VARIANTS.map(value => ({ value, label: value }))`) with `initialValue` parsed from the current file, so an invalid current value falls back to the first option.
- `modelOptions(catalogue, engine, runtime, { memory })` builds the multiselect: `value` and `label` are the id, the `hint` joins label, engine model name, the memory as `formatMemory()` renders it (`~6 GB RAM`, `VRAM` on a `gpu-*` runtime), a yellow `over the <N> GB of docker memory` when the estimate exceeds the detected docker memory on a cpu runtime, the note and a yellow `not on <runtime>` when disabled (`styleText` stays plain without a TTY or with `NO_COLOR`); `required: false`; `initialValues` are the ids of the current `AI_MODELS` that are enabled.
- After the selection, `models select` prints the endpoints n8n uses (`logModelEndpoints`): `http://ollama:11434`, or `http://vllm-<id>:8000/v1` plus the `VLLM_API_KEY` note per model, the id being the `id` of the catalogue entry (`vllmContainerName` mirrors the vllm compose `container_name`).

## Schemas as the value source

- `AI_RUNTIMES`, `AI_ENGINES`, `N8N_VARIANTS` in `src/schemas/config.ts` are the typed source of every option list. Their mirrors: the `N8N_VARIANT_CASCADE` keys in `src/commands/tilt.ts` (typed, so the compiler enforces it), the `Options:` comments in the root `.env.template`, the `runtimes` enum in `compose/models/models.schema.json`, the Configuration block of SPEC.md, and one `<engine>-<runtime>` service per runtime in each engine compose file. The first entry is the default everywhere. `AI_GATEWAYS` is the exception: no gateway runs by default, so `aiGatewaySchema` puts the empty value first, `configSchema` defaults a missing key to it and the template leaves `AI_GATEWAY=` empty; its mirrors are the `Options:` comment, `GATEWAYS` in `src/utils/models.ts` and `gatewayProjects()` in `src/commands/tilt.ts`.
- `src/schemas/models.ts` is the shape of `compose/models/models.json`, mirrored by `compose/models/models.schema.json` for editors: one `models` list, each model `.strict()` with `id` (a DNS label of at most 58 characters, unique), `label` and an `ollama` and/or `vllm` block (`.strict()`, at least one) holding `model`, `memory` (a positive number of GB), `note` (non-empty), `runtimes` (optional, non-empty when present) and, for vllm, `args`. `engineEntries()` flattens a block to the `ModelEntry` (`{ id, label, ...block }`) the rest of the CLI works with. Tests check that the repository catalogue serves every model on both engines and that the editor schema carries the same pattern, length, blocks and types.
- `src/schemas/secrets.ts` is the shape of a `.env.secrets.json` (a discriminated union on `source`, defaults for `rotation`, `bytes`, `encoding` and `prefix`, `required` typed by the config enums), mirrored by `compose/.env.secrets.schema.json`; cross-manifest rules (a link resolves to a non-link entry) live in `readSecretManifests`, template and compose rules in the repository test of `tests/secrets.test.ts`.
- `src/schemas/tilt.ts` is the shape of the `tilt resources` output, `.strict()` throughout, with refinements over the whole plan (unique names, known dependencies, enabled resources only depend on enabled ones). `tiltResources()` parses its own result through it before printing.

## Testing practices

- vitest without a config file; `pnpm -r run test` from the root runs every workspace's tests.
- `vi.mock('@clack/prompts', () => ({...}))` wholesale: `intro`, `outro`, `cancel`, `log.*` and the prompt functions as `vi.fn()` driven per test (`textMock.mockResolvedValueOnce(...)`); a cancel is simulated with a hoisted `CANCEL` symbol and a custom `isCancel`.
- Every test gets a fresh `mkdtemp` root and removes it in `afterEach`; docker is a fake `DockerRunner` that inspects `args` (`['network', 'ls', ...]`, `['network', 'create', ...]`) and returns stdout.
- `process.exitCode` and the log level are reset in `afterEach`; tests that expect an exit code save and restore the previous value.
- Tests are part of the TypeScript project, so `typecheck` covers them. `pnpm -r run test`, `pnpm --filter n8n-starter-cli run typecheck` and `pnpm -r run build` must all pass.

## Gotchas

- `--version` reads `../package.json` relative to `dist/index.mjs` (`import.meta.url`): keep the bundle one level below `package.json`. It prints `0.0.0` today.
- The root scripts pass only the command name; test flags against the bundle directly (`node packages/cli/dist/index.mjs verify --log-level error`).
- SPEC.md says `pnpm typecheck`; there is no root script of that name. Use `pnpm --filter n8n-starter-cli run typecheck` or run it inside `packages/cli/`.
- Platform detection (`detectPlatform`) runs in `setup`, `verify`, `config AI_RUNTIME` and the `models select` prompt (also reached through `config AI_MODELS`) only, always through the injectable `run`; tests pass a fake `info` answer and the host seams (`arch`, `os`, `totalmem`, `exists`) or the result depends on the machine running them. A mismatch is a warning everywhere, never a failure or an exit code.
- The CLI never runs Tilt; the Tiltfile calls `verify` and `tilt resources`, not the other way round. `tilt resources` describes what the Tiltfile should register, in Tilt's own vocabulary (`dc_resource` keyword names), without importing anything Tilt-specific.

## Recipes

### Add a command

1. `src/commands/<name>.ts`: export the logic (`doSomething(rootDir, ...)`) separately from the command function (`<name>(rootDir = process.cwd(), docker = {})`) that owns `logger.intro` / `logger.outro` and the prompts; inject `rootDir` and `run`.
2. `src/help.ts`: the table entry (`usage`, `description`, `subcommands` with `name`, `usage` and `description` when the command needs one); `src/index.ts`: the `case` and any new flags (short aliases and value-less flags into `boolean`). The dispatcher derives the sub-command checks and the help from the table.
3. `tests/<name>.test.ts` with the clack mock, a temp root and a fake docker runner where needed.
4. A root `package.json` script (`"<name>": "node packages/cli/dist/index.mjs <name>"`) when it should be a root wrapper; the command table in `packages/cli/README.md`; the CLI table and root script table in SPEC.md; the palette in `AGENTS.md` when agents should use it.
5. Validate (below), then run the built command once by hand.

### Add a root `.env` key

1. `src/schemas/config.ts`: the schema and the `configSchema` field (plus a const tuple when it is an enum).
2. `src/commands/config.ts`: the key in `CONFIG_KEYS` (template order) and `CONFIG_KEY_DESCRIPTIONS` (the template comment), its prompt function and the branch that picks it; a validation rule in `validateValue` when a schema check is not enough.
3. The root `.env.template` (a comment line above the key, an `Options:` comment for enums), the `KEY:` line of `HELP`, the Tiltfile read (`os.getenv`) and validation, the Configuration block of SPEC.md, `tests/config.test.ts` (`VALID_CONFIG`, the template-defaults and the key-mirror tests).

### Add a catalogue field

1. `src/schemas/models.ts` (a model field or a block field, keep `.strict()`), `compose/models/models.schema.json`, `ModelRecord` and `listModels()` in `src/utils/models.ts` so `models read` prints it, and `modelOptions()` when the field belongs in the hint or affects `disabled`.
2. The fixtures in `tests/models.test.ts`, `tests/config.test.ts`, `tests/models-command.test.ts` and `tests/tilt.test.ts`; the entries table in SPEC.md; `modelProjects()` in `src/commands/tilt.ts` only when the field reaches a container.

### Change the Tilt plan (a service, a dependency, a link, what a variant enables)

1. `tiltResources()` in `src/commands/tilt.ts`: the `project(...)`/`resource(...)` entry, with `enabled` and `auto_init` as the variant requires; the schema in `src/schemas/tilt.ts` only when the shape changes (then the loop in the Tiltfile too).
2. `tests/tilt.test.ts`: the expected names per variant and the repository test (every file of the plan must exist).
3. The Tilt section of SPEC.md; `compose-catalogue.md` (How Tilt consumes the catalogue).
4. Validate: typecheck + build + test; `node packages/cli/dist/index.mjs tilt resources --log-level error`; `tilt alpha tiltfile-result -v`.
